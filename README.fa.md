## <a id="intro"></a>👋 ktOperator دقیقاً چیه؟

‏**ktOperator** یه عامل هوش مصنوعیِ ترمینالیه که واقعاً می‌تونی کامپیوترت رو بهش بسپری. کارت رو با زبون خودت بهش می‌گی — *مثلا: این پروژه رو تحلیل کن*، *چی داره از پورت ۳۰۰۰ استفاده می‌کنه؟*، *Opera GX رو باز کن*، *تو D:/docs یه فایل بساز* — اونم برنامه‌ریزی می‌کنه، می‌خونه، می‌نویسه، دستور اجرا می‌کنه و آخرش کار خودش رو هم چک می‌کنه؛ اون هم فقط داخل پوشه‌ای (همون فضای کاری) که خودت اجازه دادی.

ایدهٔ اصلی ساده‌ست، ولی سخت‌گیرانه:

> **مدل پیشنهاد می‌ده. موتور سیاست تصمیم می‌گیره.**

هوش مصنوعی هر چیزی رو می‌تونه پیشنهاد بده، ولی هیچ‌وقت نمی‌تونه کار خودش رو تأیید کنه، بدون سندباکس دستور اجرا کنه، بیرون از فضای کاری چیزی بخونه یا کلیدهای API تو رو ببینه. هر اقدامی از یه مسیر ثابت رد می‌شه: بررسی طرح‌واره ← سطح ریسک ← رأی موتور سیاست ← تأیید خودت (اگه لازم باشه) ← اجرا تو سندباکس ← پوشوندن اطلاعات حساس ← ثبت تو گزارش حسابرسی.

### چه کارهایی ازش برمیاد؟

- **فهمیدن کد** — توضیح یه پروژه، پیدا کردن جای پیاده‌سازی یه قابلیت، بررسی یه فایل
- **تغییر امنِ کد** — ساختن، ویرایش، جابه‌جایی و حذف فایل و پوشه (قبل از هر تغییر یه نسخهٔ پشتیبان گرفته می‌شه و هر ویرایش، diff نشونت می‌ده)
- **اجرای کارها** — تست، typecheck، lint، build و دستورهای واقعی شل مثل `ipconfig`، `df -h` و `git status`
- **کارهای طولانی** — روشن کردن سرور توسعه تو پس‌زمینه، خوندن خروجیش خط‌به‌خط و خاموش کردنش وقتی کارت تموم شد
- **کار با کامپیوتر خودت** — باز کردن هر برنامهٔ نصب‌شده با اسمش، بستن یه برنامه، باز کردن یه صفحهٔ وب تو مرورگر
- **دسترسی به بیرون از فضای کاری** — وقتی به یه پوشه یا درایو دیگه اشاره می‌کنی، به‌جای اینکه بگه «دسترسی ندارم»، یه بار ازت اجازه می‌گیره
- **برگردوندن هر تغییر** — قبل از هر کار یه نقطهٔ بازگردانی ثبت می‌شه؛ `/undo` برت می‌گردونه و `/diff` دقیق نشونت می‌ده چی عوض شده

## <a id="install"></a>🚀 نصب

پیش‌نیاز: **Node.js نسخهٔ ۲۲٫۱۲ یا بالاتر**. داکر اختیاریه، ولی قوی‌ترین سندباکس رو بهت می‌ده (بار اول خودش به‌صورت خودکار دانلود می‌شه). هر دو دستور `ktoperator` و `operator` از یه پکیج میان — یعنی یه برنامهٔ واحد.

## <a id="quickstart"></a>🎯 شروع سریع — کنسول تعاملی

<div dir="ltr">

```bash
ktoperator
```

</div>

بار اول، کنسول قدم‌به‌قدم راهنمایی‌ت می‌کنه تا برسی به کادر گفتگو. از اجرای بعدی مستقیم می‌ری تو کادر گفتگو.

| # | مرحله | چی می‌شه |
|---|---|---|
| ۱ | **ارائه‌دهنده** | یکی رو انتخاب می‌کنی: OpenRouter، OpenAI، Anthropic، Google Gemini، هر نقطهٔ پایانی سازگار با OpenAI، یا Ollama محلی |
| ۲ | **کلید API** | مخفیانه تایپ می‌شه، با `chmod 600` ذخیره می‌شه و همون لحظه اتصال تست می‌شه |
| ۳ | **مدل** | فهرست زندهٔ مدل‌های ارائه‌دهنده‌ت رو می‌بینی — یکی رو انتخاب کن یا شناسهٔ مدل رو دستی بنویس |
| ۴ | **فضای کاری** | **فقط یه پوشه** رو مجاز می‌کنی که عامل بتونه توش بخونه و تغییر بده |
| ۵ | **سندباکس** | بک‌اندهای ایزوله‌سازیِ در دسترس رو نشونت می‌ده (داکر اولویت داره) |
| ۶ | **کادر گفتگو** | هر کاری خواستی بنویس. تأییدها، diff‌های رنگی و خروجی ابزارها همون‌جا نشون داده می‌شه |

### کادر گفتگو

- **Enter** پیام رو می‌فرسته و **Ctrl+J** (یا Alt+Enter) یه خط جدید باز می‌کنه، برای پیام‌های بلند
- **↑ / ↓** پیام‌های قبلیت رو برمی‌گردونه
- **/** (اسلش) منوی دستورها رو باز می‌کنه — جستجوش فازیه (`/tatus` هم `/status` رو پیدا می‌کنه)، با ↑↓ جابه‌جا می‌شی و وقتی فاصله بزنی منو بسته نمی‌شه، پس دستورهای دوکلمه‌ای مثل `/provider delete` زیرمنوهاشون رو برای انتخاب نشون می‌دن
- گوشهٔ بالا-راست هزینه و تعداد توکنِ زندهٔ همین نشست رو می‌بینی؛ درصد زمینه هم تو پنل `/usage` هست
- **Ctrl+C** فقط دو کار می‌کنه، نه سه‌تا: وسط اجرای یه کار، فقط همون کار رو متوقف می‌کنه؛ تو پیام خالی، خط رو پاک می‌کنه و اگه دوباره زیر ۲ ثانیه بزنیش، از کنسول بیرون می‌ری. `/exit` هم همیشه کار می‌کنه

### خروج و برگشت

وقتی خارج می‌شی، کنسول دو خط چاپ می‌کنه:

<div dir="ltr">

```text
✦ Goodbye
to continue this chat, enter ktoperator <sessionId>
```

</div>

بعداً با `ktoperator <sessionId>` (یا `ktoperator chat <sessionId>`) همون گفتگو رو با تاریخچهٔ فشرده‌ش به‌عنوان زمینه باز می‌کنی. اگه شناسه رو اشتباه بزنی، یه پیغام دوستانه می‌گیری که به `ktoperator session list` اشاره می‌کنه.

## <a id="console"></a>⌨️ دستورهای کنسول (`/...`)

برای فهرست دسته‌بندی‌شده `/help` رو بزن، یا فقط `/` رو تایپ کن تا منوی تعاملی بیاد. دستورهای فاصله‌دار (مثل `/provider delete`) زیرمنوهاشون رو تو منو پیشنهاد می‌دن — لازم نیست کلمهٔ دوم رو دستی تایپ کنی.

### نشست

| دستور | چی کار می‌کنه |
|---|---|
| `/status` | داشبورد: نشست، ارائه‌دهنده، مدل، فضای کاری، سندباکس، مصرف |
| `/usage` | تفکیک توکن، کش و هزینهٔ همین نشست (مصرف زمینه نسبت به بودجه، نرخ برخورد کش، باقی‌ماندهٔ سقف هزینه) |
| `/resume [id]` | یه نشست قبلی رو ادامه می‌ده — زمینه خودکار فشرده می‌شه |
| `/sessions` | نشست‌های قبلی رو مدیریت می‌کنه: فهرست، `delete <id>` (با انتخاب‌گر یا پیشوند شناسه، همراه تأیید) یا `clear` برای پاک کردن همه. نشستی که بازه، محافظت می‌شه |
| `/export [id] [--out file]` | از یه نشست خروجی Markdown می‌گیره |
| `/checkpoint [label]` | یه نقطهٔ بازگردانی ثبت می‌کنه (قبل از هر کار هم خودکار یکی ثبت می‌شه). `/checkpoint list` فهرستش رو نشون می‌ده |
| `/undo [n]` | فضای کاری رو به نقطهٔ بازگردانی *n* برمی‌گردونه (پیش‌فرض: آخرین). اول پیش‌نمایش diff رنگی نشونت می‌ده و تأیید می‌گیره |
| `/diff [n]` | تغییرات از نقطهٔ بازگردانی *n* رو خط‌به‌خط نشون می‌ده — `+` سبز و `-` قرمز |

### راه‌اندازی

| دستور | چی کار می‌کنه |
|---|---|
| `/provider` | فهرست پروفایل‌ها؛ `use <id>` برای عوض کردن، `add` برای ساختن پروفایل جدید، `delete <id>` برای حذف (با اعتبارنامه‌هاش). اگه پروفایل فعال رو حذف کنی می‌ره روی یکی دیگه؛ آخرین پروفایل محافظت می‌شه |
| `/model` | مدل فعلی رو نشون می‌ده؛ `use <id>` برای عوض کردن، `reload` برای بارگذاری دوبارهٔ فهرست مدل‌ها |
| `/workspace [path]` | فضای کاری مجاز رو نشون می‌ده، یا یه مسیر رو دوباره مجاز می‌کنه |
| `/access [list\|clear]` | پوشه‌ها/درایوهایی که تو این نشست بیرون از فضای کاری مجاز کردی رو نشون می‌ده یا لغو می‌کنه |
| `/skill` | مهارت‌های `.operator/skills`: ‏`list`، ‏`use <n>`، ‏`add <n>` (ویرایشگر چندخطی)، ‏`show <n>`، ‏`delete <n>` |
| `/prompt` | قالب‌های پرامپت `.operator/prompts`: ‏`list`، ‏`use <n>`، ‏`add <n>`، ‏`delete <n>` |

### سیستم

| دستور | چی کار می‌کنه |
|---|---|
| `/sandbox` | بک‌اندهای سندباکس، در دسترس بودنشون و بک‌اند فعال |
| `/doctor` | عیب‌یابی کامل محیط (زمان اجرا، تنظیمات، ارائه‌دهنده‌ها، فضای کاری، سندباکس) |
| `/clear` | نمای گفتگو و زمینه رو پاک می‌کنه |
| `/exit` (اسم دیگه‌ش `/quit`) | از کنسول خارج می‌شی |

### نقطهٔ بازگردانی، `/undo` و diff — خودمونی

هر بار که یه کار می‌فرستی، ktOperator بی‌سروصدا یه **نقطهٔ بازگردانی** ثبت می‌کنه؛ یعنی یه علامت تو فهرست پشتیبان‌های فایل. بعد از اینکه کار انجام شد، یه **پیش‌نمایش diff** می‌بینی (`+` سبز برای چیزهای اضافه‌شده، `-` قرمز برای حذف‌شده‌ها) که دقیقاً نشون می‌ده چی عوض شده. اگه خوشت نیومد، `/undo` فایل‌ها رو به قبل از اون کار برمی‌گردونه — اول پیش‌نمایش رو نشونت می‌ده، تأیید می‌گیره و فقط چیزهایی رو برمی‌گردونه که بعد از اون نقطه تغییر کردن. `/undo 2` هم تا نقطهٔ بازگردانی دوم عقب می‌بره. دستورهایی که قبلاً اجرا شدن (نصب، درخواست‌های شبکه) برگشت‌پذیر نیستن — فقط محتوای فایل‌ها برمی‌گرده و کنسول این رو بهت یادآوری می‌کنه.

### مهارت‌ها، پرامپت‌ها و پوشهٔ `.operator/`

وقتی کنسول رو تو یه مسیر باز می‌کنی، اونجا یه پوشهٔ `.operator/` می‌سازه:

<div dir="ltr">

```text
.operator/
  README.md          این پوشه چیه
  .gitignore         sessions/ نادیده گرفته می‌شه (شخصیه)؛ مهارت‌ها/پرامپت‌ها قابل کامیت‌ان
  skills/*.md        مهارت‌های قابل استفادهٔ دوباره
  prompts/*.md       قالب‌های پرامپت
  sessions/<id>.md   آینهٔ خوانای هر گفتگو تو این مسیر
```

</div>

- **مهارت‌ها** راهنماهای markdown هستن. با `/skill add review-code` یه مهارت می‌نویسی و با `/skill use review-code` تو گفتگوی فعلی بارگذاریش می‌کنی. وقتی کنسول جدیدی تو همون مسیر باز بشه، می‌گه چند تا گفتگوی قبلی تو این مسیر ذخیره شده و قبل از بارگذاری هر مهارت یا پرامپت ازت تأیید می‌گیره (اول محتوا تو یه کادر نشون داده می‌شه — یعنی فایل‌های یه ریپوی کلون‌شده هیچ‌وقت نمی‌تونن بی‌سروصدا دستور تزریق کنن).
- **پرامپت‌ها** نقطهٔ شروع‌های آماده‌ان: با `/prompt add standup` یه قالب می‌نویسی و با `/prompt use standup` گفتگو رو ازش شروع می‌کنی.
- **آینه‌های گفتگو** بعد از هر کار نوشته می‌شن، پس تاریخچه‌ت تو اون پوشه همیشه به‌شکل markdown خوانا دم دسته.
- مهارت‌ها و پرامپت‌ها رو می‌تونی تو گیت کامیت کنی و با تیمت به اشتراک بذاری؛ آینه‌های گفتگو محلی می‌مونن.

### قوانین پروژه (`AGENTS.md`)

اگه تو فضای کاری‌ت فایل `AGENTS.md` (یا `.operator/instructions.md`) باشه، کنسول فایل رو نشونت می‌ده و قبل از بارگذاری ازت تأیید می‌گیره. جوابت بر اساس هش دقیق محتوا یادش می‌مونه: فایل‌های بدون تغییر دوباره پرسیده نمی‌شن و اگه فایل ویرایش بشه، دوباره تأیید می‌خواد. دستورهای تأییدشده فقط تعیین می‌کنن کار *چطوری* انجام بشه — هیچ‌وقت نمی‌تونن دسترسی بدن، اقدامی رو تأیید کنن یا امنیت رو ضعیف کنن.

## <a id="cli"></a>🧾 خط فرمان (CLI)

همهٔ کارهای کنسول رو به‌شکل دستورِ قابل اسکریپت‌نویسی هم داری. پرچم‌های سراسری: `--json` (خروجی ماشینی، غیرتعاملی) · `--no-color` · `-v, --version`.

| دستور | چی کار می‌کنه |
|---|---|
| `ktoperator` · `operator chat [sessionId]` | کنسول تعاملی (پیش‌فرض). با شناسهٔ نشست، همون گفتگو رو ادامه می‌ده |
| `operator run <task...>` | یه کار رو از اول تا آخر اجرا می‌کنه و خارج می‌شه. گزینه‌ها: `--provider <id>`، `--model <id>`، `--yes [read\|write\|all]`، `--dry-run`، `--max-steps <n>`، `--token-budget <n>` |
| `operator plan <task...>` | فقط برنامهٔ اجرا رو چاپ می‌کنه — هیچ‌چیز اجرا یا تغییر داده نمی‌شه |
| `operator init` | خانهٔ تنظیمات و تنظیمات پیش‌فرض رو می‌سازه (اختیاری: انتخاب فضای کاری) |
| `operator doctor` | عیب‌یابی محیط: زمان اجرا، تنظیمات، ارائه‌دهنده‌ها، فضای کاری، سندباکس |
| `operator provider list` | فهرست پروفایل‌های ارائه‌دهنده (کلیدها هیچ‌وقت چاپ نمی‌شن) |
| `operator provider add ...` | یه پروفایل اضافه می‌کنه: `--id`، `--type`، `--base-url`، `--model`، `--api-key-env`، `--key`، `--referer`، `--title`، `--trusted-local`، `--default`، `--skip-test` |
| `operator provider test [id]` | اتصال و احراز هویت یه پروفایل رو تست می‌کنه |
| `operator provider remove <id>` (اسم دیگه‌ش `delete`) | یه پروفایل و اعتبارنامه‌های ذخیره‌شده‌ش رو حذف می‌کنه |
| `operator model list [--provider <id>]` | مدل‌ها و قابلیت‌های یه ارائه‌دهنده رو فهرست می‌کنه |
| `operator workspace select [path]` | یه پوشه رو به‌عنوان فضای کاری مجاز می‌کنه (پیش‌فرض: پوشهٔ فعلی) |
| `operator workspace show` | فضای کاری فعلی رو نشون می‌ده و می‌گه معتبره یا نه |
| `operator session list [--limit <n>]` | نشست‌های اخیر رو فهرست می‌کنه |
| `operator session delete <id>` | یه نشست رو برای همیشه پاک می‌کنه (با شناسه یا پیشوندش) |
| `operator session export <id> [--out <file>]` | از یه نشست خروجی Markdown می‌گیره |
| `operator usage [sessionId]` | تفکیک توکن/کش/هزینه برای یه نشست، یا جمع کل همهٔ نشست‌ها |
| `operator history [sessionId] [--limit <n>]` | ردپای حسابرسی، یا رونوشت کامل یه نشست |
| `operator sandbox status` | بک‌اندهای سندباکس، در دسترس بودن، قابلیت‌ها و انتخاب فعال |
| `operator config show` | تنظیمات مؤثر (اطلاعات حساس پوشونده‌شده) |
| `operator config set <key> <value>` | یه تنظیم اعتبارسنجی‌شده رو ست می‌کنه (بخش تنظیمات پایین‌تر) |
| `operator config path` | مسیر فایل تنظیمات رو چاپ می‌کنه |
| `operator backups [sessionId]` | پشتیبان‌های قابل بازیابی رو فهرست می‌کنه (همهٔ نشست‌ها یا فقط یکی) |
| `operator rollback <sessionId> [--yes]` | فایل‌های تغییرکردهٔ یه نشست رو از پشتیبان‌هاش برمی‌گردونه |

چند نمونه:

<div dir="ltr">

```bash
operator run 'تست‌های خراب را رفع و تغییرات را خلاصه کن' --dry-run
operator run 'یک بخش به README اضافه کن' --yes write
operator run 'این پروژه را تحلیل کن' --token-budget 50000 --json
operator provider add --id openrouter --type openrouter --model anthropic/claude-sonnet-4.5 --default
operator session export 74c48d0d --out chat.md
operator rollback 74c48d0d
```

</div>

سطح‌های `--yes`: `read` فقط خوندن‌های سطح ۰ رو خودکار تأیید می‌کنه، `write` سطح‌های ۰ تا ۱ رو و `all` همه‌چیز رو (همه ثبت و حسابرسی می‌شن؛ کارهای مخرب هم باز اول پشتیبان می‌گیرن). `--dry-run` برنامه رو بدون هیچ تغییری شبیه‌سازی می‌کنه. تو حالت غیرتعاملی اگه `--yes` ندی، هر چیزی که تأیید می‌خواد با یه توضیح روشن رد می‌شه.

## <a id="providers"></a>🔌 ارائه‌دهنده‌ها و مدل‌ها

شش نوع ارائه‌دهنده، همه با یه رابط یکسان. خطاها هم همه‌جا یه شکلن: احراز هویت، اعتبار، محدودیت نرخ (با رعایت `Retry-After`)، در دسترس بودن مدل، شبکه و تایم‌اوت.

| ارائه‌دهنده | چطوری وصل می‌شه | نکته‌ها |
|---|---|---|
| 🟠 **OpenRouter** (درجه یک) | `OPENROUTER_API_KEY` | کشف زندهٔ مدل، تشخیص فراخوانی ابزار برای هر مدل، گزارش توکن و هزینه، گزارش توکن‌های کش‌شده |
| 🟢 **OpenAI** | `OPENAI_API_KEY` | گزارش توکن‌های کش پرامپت |
| 🟠 **Anthropic** | `ANTHROPIC_API_KEY` | پرامپت سیستم با کش پرامپتِ فعال فرستاده می‌شه |
| 🔵 **Google Gemini** | `GOOGLE_API_KEY` | API بومی؛ کلید تو هدر می‌ره، هیچ‌وقت تو URL نمی‌ره؛ طرح‌واره‌های ابزار طوری فیلتر می‌شن که Gemini قبول کنه |
| 🔗 **سازگار با OpenAI** | هر نقطهٔ پایانی + `--base-url` | اعتبارسنجی SSRF: فقط HTTPS، بدون اعتبارنامه تو URL، بدون ریدایرکت؛ آدرس‌های خصوصی فقط با `--trusted-local` |
| 🐳 **Ollama** | محلی، بدون کلید | استنتاج محلی و آفلاین (`http://127.0.0.1:11434/v1` به‌صورت پیش‌فرض) |

کلیدها به این ترتیب پیدا می‌شن: متغیر محیطیِ پروفایلت ← متغیر محیطیِ پیش‌فرض ارائه‌دهنده ← انبار محلیِ محافظت‌شده (`chmod 600`). کلیدها هیچ‌وقت چاپ، لاگ یا تو فضای کاری نوشته نمی‌شن و جایی جز نقطهٔ پایانی ارائه‌دهنده فرستاده نمی‌شن.

**جایگزینی خودکار ارائه‌دهنده (اختیاری):** اگه ارائه‌دهندهٔ اصلیت محدودیت نرخ بخوره یا اعتبارش تموم بشه، اجرا می‌تونه به‌جای اینکه وایسته، روی پروفایل بعدی ادامه پیدا کنه — و هر جابه‌جایی همیشه بهت اعلام می‌شه. با `operator config set fallback.enabled true` روشنش کن (اختیاری: `fallback.order openrouter,openai`). هیچ‌وقت بی‌صدا جابه‌جا نمی‌شه، هیچ‌وقت بعد از اینکه متن جواب رو صفحه اومده، و هیچ‌وقت برای خطاهای احراز هویت یا درخواست بد.

## <a id="tools"></a>🧰 ۴۰ ابزار عامل

عامل هیچ‌وقت مستقیم به کامپیوترت دست نمی‌زنه — فقط می‌تونه این ابزارها رو درخواست کنه و هر فراخوانی اول از مسیر امنیتی رد می‌شه.

| گروه | ابزارها | چی کار می‌کنن |
|---|---|---|
| 📁 فایل (خوندن) | `list_directory`، `read_file`، `search_files`، `search_text`، `inspect_file_metadata`، `generate_diff` | گشتن و خوندن فضای کاری؛ پیش‌نمایش diff قبل از هر تغییر |
| ✏️ نوشتن | `create_file`، `edit_file`، `move_file`، `delete_file`، `delete_directory` | ساختن، ویرایش (با پیش‌نمایش diff و تحمل فاصله)، جابه‌جایی و حذف. قبل از هر نوشتن پشتیبان گرفته می‌شه؛ حذف پوشه حداکثر ۵۰۰ فایل / ۵۰ مگابایته و هیچ‌وقت به ریشهٔ فضای کاری یا `.git` دست نمی‌زنه |
| 🔎 پروژه و گیت | `inspect_project`، `detect_project_type`، `inspect_package_json`، `inspect_git_status`، `git_commit`، `git_branch`، `git_stash` | فهمیدن پروژه و کارهای گیت (استیج همه + کامیت، فهرست/ساخت/جابه‌جایی شاخه، stash) — داخل سندباکس و با تأیید |
| 🧪 کیفیت | `run_tests`، `run_typecheck`، `run_linter`، `run_build` | فقط اسکریپت‌های موجود `test` / `typecheck` / `lint` / `build` پروژه رو اجرا می‌کنن |
| 📊 اطلاعات سیستم | `get_operating_system`، `get_runtime_versions`، `get_cpu_summary`، `get_memory_summary`، `get_disk_usage`، `get_process_summary` | اطلاعات فقط-خواندنیِ دستگاه برای سؤال‌هایی مثل «چقدر فضا خالی مونده» |
| ⚙️ دستورها | `execute_approved_command`، `run_shell_command`، `start_background_process`، `read_process_output`، `inspect_command_result`، `terminate_managed_process` | اجرای دستورهای ساخت‌یافته تو سندباکس، خط‌های واقعی cmd/bash/PowerShell روی دستگاه خودت (متن دقیقش اول تأیید می‌شه) و کارهای طولانی پس‌زمینه با خروجی محدود |
| 🌐 وب | `web_search`، `web_fetch` | اینترنت عمومی، فقط برای خوندن. هر URL و ریدایرکت اعتبارسنجی می‌شه (فقط http(s)، بدون آدرس خصوصی)، خروجی محدوده، پوشونده و از نظر تزریق غربال می‌شه |
| 🗝️ دسترسی | `request_path_access` | ازت یه پوشه/درایو بیرون از فضای کاری رو می‌خواد — پیش‌فرض فقط‌خواندنی؛ خوندن+نوشتن فقط با تأیید جدا |
| 🖥️ دسکتاپ | `launch_app`، `open_url`، `close_app` | باز کردن هر برنامهٔ نصب‌شده با اسم، باز کردن URL تو مرورگر و بستن یه برنامهٔ در حال اجرا. شل‌ها و ترمینال‌ها با اسم رد می‌شن؛ هیچ‌چیز نمی‌تونه نصب، دانلود یا کلیک کنه |

بعد از هر اجرا، یه **کادر تغییرات** خلاصه می‌کنه دقیقاً چی عوض شده (پوشه‌ها، فایل‌ها، برنامه‌ها، لینک‌ها، دستورها) و **پیش‌نمایش diff** تغییرات فایل‌ها رو خط‌به‌خط و رنگی نشون می‌ده.

### مقصد دقیق — بدون فایل تکراری

وقتی یه مقصد مطلق می‌گی («تو D:/docs/notes.txt یه فایل بساز»)، فایل **دقیقاً همون‌جا و فقط یه بار** ساخته می‌شه. یه نگهبانِ زمان‌اجرا تو حلقهٔ عامل هر فایل هم‌اسمی رو که اشتباهی تو پوشهٔ فضای کاری/ترمینال ساخته بشه مسدود می‌کنه و مقصد دقیق رو به عامل یادآوری می‌کنه.

## <a id="security"></a>🛡️ مدل امنیتی

> مدل پیشنهاد می‌ده. موتور سیاست تصمیم می‌گیره.

| لایه | برای تو یعنی چی |
|---|---|
| **مرز فضای کاری** | هر دسترسی به فایل از طریق فایل‌سیستم واقعی بررسی می‌شه (`realpath`)، پس فرار با symlink/junction، پیمایش `..` و جابه‌جایی TOCTOU به دیوار می‌خورن. فقط فایل‌ها و پوشه‌های معمولی — هیچ‌وقت دستگاه، سوکت یا FIFO |
| **سندباکس یا هیچ** | دستورها تو داکر اجرا می‌شن: به‌صورت پیش‌فرض بدون شبکه، با قابلیت‌های حذف‌شده، ریشهٔ فقط-خواندنی و محدودیت حافظه/CPU/pid. ایمیج بار اول خودکار دانلود می‌شه. بدون سندباکس، اجرا **رد** می‌شه — هیچ‌وقت بی‌صدا سخت‌گیری رو کم نمی‌کنه. شل واقعی روی هاست یه تصمیم جدا از نوع سطح ۳ و برای هر دستوره و متن دقیقش نشونت داده می‌شه |
| **۴ سطح تأیید** | سطح ۰ خوندن (مجاز) ← سطح ۱ نوشتن برگشت‌پذیر (تأیید) ← سطح ۲ مخرب (تأیید برای هر عملیات، هیچ‌وقت برای کل نشست) ← سطح ۳ ویژه/خارجی (برای هر عملیات، با حسابرسی پررنگ). هوش مصنوعی هیچ‌وقت خودش رو تأیید نمی‌کنه؛ سه بار رد شدن، اجرا رو متوقف می‌کنه |
| **سیاست هر ابزار** | `security.toolPolicies` می‌تونه هر ابزار رو `allow`، `approve` یا `deny` کنه. توضیحات ابزاری که متن شبه‌دستوری دارن تو گزارش حسابرسی پرچم می‌خورن (دفاع در برابر مسموم‌سازی ابزار) |
| **دفاع در برابر تزریق** | هر چیزی که ابزارها برمی‌گردونن به‌عنوان دادهٔ غیرقابل‌اعتماد بسته‌بندی و غربال می‌شه؛ دستورهای پروژهٔ تأییدشده با هش محتوا یادشون می‌مونه و هیچ‌وقت نمی‌تونن دسترسی بدن |
| **دفاع از رازها** | پوشوندن الگو-محور کلیدها/توکن‌ها تو همهٔ خروجی‌هایی که مدل می‌بینه، تو ورودی‌های حسابرسی، خطاها و نمای تنظیمات؛ نوشتن‌هایی که شبیه راز زنده‌ان رد می‌شن (`security.blockSecretWrites`، پیش‌فرض روشن) |
| **حسابرسی و بازیابی** | گزارش حسابرسی JSONL از هر درخواست، تصمیم، اجرا، پشتیبان و بازیابی. قبل از هر تغییر پشتیبان فایل؛ `operator rollback` یا `/undo` برشون می‌گردونه. دستورهایی که قبلاً اجرا شدن برگشت‌پذیر نیستن — و رابط کاربری هم همین رو می‌گه |
| **محافظت در برابر اجرای بی‌پایان** | بودجهٔ تکرار/فراخوانی ابزار/زمان، تشخیص گیر کردن (تکرار یه فراخوانی ۳ بار)، لغوی که به ارائه‌دهنده‌ها، ابزارها و درخت فرایندها می‌رسه و نگهبان مقصد دقیق |

جزئیات بیشتر: [مدل امنیتی](docs/security.md) · [ماتریس دسترسی](docs/permissions.md) · [سندباکس](docs/sandbox.md) · [معماری](docs/architecture.md)

## <a id="cost"></a>💰 کنترل توکن و هزینه

ktOperator جوری ساخته شده که اجراش ارزون باشه، نه فقط توانمند:

- **کش پرامپت** — Anthropic روی پرامپت سیستمِ ثابت `cache_control` می‌گیره و OpenAI/OpenRouter توکن‌های `cached_tokens` رو گزارش می‌کنن. ارزون‌ترین توکن‌های هر درخواست همون کش‌شده‌هان
- **بودجهٔ زمینه** — `limits.tokenBudget` (پیش‌فرض ۳۰٬۰۰۰). نوبت‌های قدیمی اول به یه خلاصهٔ یک‌خطی فشرده می‌شن و بعد حذف می‌شن — کار و وظیفهٔ تازه هیچ‌وقت از بین نمی‌ره. `/usage` میزان مصرف رو نشون می‌ده و تو ۸۰٪ یه بار هشدار می‌گیری
- **سقف هزینه** — `limits.costCapUsd` وقتی هزینهٔ گزارش‌شده از سقف رد بشه، اجرا رو با دلیل روشن متوقف می‌کنه
- **ادامهٔ فشرده** — `/resume` و `ktoperator <id>` وظیفهٔ اول، خلاصهٔ نوبت‌های قدیمی و آخرین نوبت‌ها رو کامل بارگذاری می‌کنن — یعنی کسری از زمینهٔ اصلی
- **خوندن موازی** — فراخوانی‌های فقط-خواندنیِ پشت‌سرهم هم‌زمان اجرا می‌شن؛ هر چیزی که تأیید بخواد همچنان ترتیبی و یکی‌یکی می‌مونه
- **نسخهٔ فشرده** — یه بیلد بدون وابستگی و کم‌مصرف تو `compact/` هست (کف توکنِ اندازه‌گیری‌شدهٔ هر نوبت حدود ۸۴٪ کمتره)

<div dir="ltr">

```bash
operator config set limits.tokenBudget 30000
operator config set limits.costCapUsd 2.50
operator run 'بازسازی بزرگ' --token-budget 50000
```

</div>

## <a id="config"></a>⚙️ تنظیمات

فایل تنظیمات با طرح‌واره اعتبارسنجی می‌شه — مقدارهای نامعتبر هیچ‌وقت بی‌صدا قبول نمی‌شن:

| سیستم‌عامل | مسیر |
|---|---|
| لینوکس | `~/.config/operator/config.json` |
| مک | `~/Library/Application Support/KarizTeam/Operator/config.json` |
| ویندوز | `%APPDATA%/KarizTeam/Operator/config.json` |

با `OPERATOR_HOME` می‌تونی یه دایرکتوری حالتِ دیگه استفاده کنی (تنظیمات، اعتبارنامه‌ها، نشست‌ها، حسابرسی، پشتیبان‌ها). `operator config path` مسیر فعال رو چاپ می‌کنه.

کلیدهای قابل تنظیم (همه با بازه بررسی می‌شن):

| کلید | چی رو کنترل می‌کنه |
|---|---|
| `defaultProvider`، `defaultModel` | پیش‌فرضی که نشست‌های جدید باهاش شروع می‌شن |
| `fallback.enabled`، `fallback.order` | زنجیرهٔ جایگزینی خودکار ارائه‌دهنده (اعلام‌شده، هیچ‌وقت بی‌صدا) |
| `security.allowRestrictedProcessFallback` | روشن کردن اختیاریِ بک‌اند غیرکانتینری برای هاست‌های بدون داکر (اول `docs/sandbox.md` رو بخون) |
| `security.maxAutoApproveTier` | سقف سخت برای تأیید خودکارِ `--yes` (۰ تا ۲) |
| `security.toolPolicies` | `allow` / `approve` / `deny` برای هر ابزار (مستقیم تو JSON تنظیمات ویرایشش کن) |
| `security.blockSecretWrites` | نوشتن‌هایی که محتواشون شبیه راز زنده‌ست رد می‌شه (پیش‌فرض روشن) |
| `sandbox.backend`، `sandbox.image`، `sandbox.network`، `sandbox.memoryMb`، `sandbox.cpus`، `sandbox.pidsLimit`، `sandbox.writableDefault`، `sandbox.autoPull` | انتخاب بک‌اند داکر و محدودیت‌هاش |
| `network.allowPrivateProviderEndpoints` | اجازه به نقاط پایانی خصوصی/لوپ‌بک ارائه‌دهنده (پیشرفته) |
| `limits.maxIterations`، `limits.maxToolCalls`، `limits.maxDurationMs`، `limits.maxOutputBytes`، `limits.maxFileBytes`، `limits.maxProcesses`، `limits.maxProviderRetries`، `limits.maxTokens`، `limits.tokenBudget`، `limits.costCapUsd` | بودجه‌ها و سقف‌های اجرا |
| `backups.enabled`، `backups.maxMb` | حجم پشتیبان فایل (پیش‌فرض ۲۵۶ مگابایت) |
| `ui.color` | رنگ‌های ANSI روشن/خاموش (یا `--no-color`) |

متغیرهای محیطی: `OPENROUTER_API_KEY`، `OPENAI_API_KEY`، `ANTHROPIC_API_KEY`، `GOOGLE_API_KEY`، `OPENAI_COMPATIBLE_API_KEY` (یا `apiKeyEnv` پروفایلت)، `OPERATOR_HOME`، `OPERATOR_DEBUG=1` (رد پشته برای خطاهای غیرمنتظره).

| علامت | راه‌حل |
|---|---|
| «ارائه‌دهندهٔ هوش مصنوعی پیکربندی نشده» | فقط `ktoperator` رو اجرا کن — کنسول راهنمایی‌ت می‌کنه. یا متغیر محیطی رو ست کن و `operator provider add --id openrouter --type openrouter --model <id> --default` رو بزن |
| احراز هویت ناموفق (401/403) | `operator provider list` منبع کلیدِ هر پروفایل رو نشون می‌ده؛ کلید رو با `/provider add` دوباره وارد کن یا متغیر محیطی درست رو ست کن؛ `operator provider test` هم چک می‌کنه |
| «فضای کاری انتخاب نشده» | `operator workspace select .` پوشهٔ فعلی رو مجاز می‌کنه |
| «سندباکس امن در دسترس نیست» | داکر رو نصب کن (`docker pull node:22-alpine`)، یا `docs/sandbox.md` رو بخون و بک‌اند فرایند محدودشده رو روشن کن. ابزارهای فقط-خواندنی به هر حال کار می‌کنن |
| «تأیید به ترمینال تعاملی نیاز دارد» | با `--json` و بدون `--yes` اجرا کردی. یا `--json` رو بردار، یا آگاهانه `--yes write` / `--yes all` بده |
| محدودیت نرخ / اعتبار (429/402) | با `Retry-After` دوباره تلاش می‌شه؛ 402 یعنی اعتبار ارائه‌دهنده تموم شده — شارژش کن، پروفایل رو عوض کن یا `fallback.enabled` رو روشن کن |
| «مدل پیدا نشد» | `operator model list --provider <id>` شناسه‌های معتبر رو چاپ می‌کنه؛ مدل‌هایی که فراخوانی ابزار ندارن نمی‌تونن کاری انجام بدن |
| یه فرایند پس‌زمینه هنوز در حال اجراست | کارها عمداً ادامه می‌دن. با `terminate_managed_process` متوقفشون کن؛ بقیه با تموم شدن نشست متوقف می‌شن |
| «اسکریپت npm پیدا نشد» | فقط اسکریپت‌های موجودِ `test`/`typecheck`/`lint`/`build` اجرا می‌شن. پیغام خطا فهرست اسکریپت‌های موجود رو نشونت می‌ده |
| خطای غیرمنتظره | با `OPERATOR_DEBUG=1` دوباره اجرا کن تا رد پشته رو بگیری |

## <a id="limits"></a>⚠️ محدودیت‌های شناخته‌شده

- بک‌اند فرایند محدودشده **کانتینر نیست**: ایزوله‌سازی فایل/شبکه نداره و محدودیت حافظه/pid هم نداره — آگاهانه و بعد از خوندن `docs/sandbox.md` روشنش کن
- سندباکس ویندوز تا وقتی بک‌اند کانتینریِ ویندوز منتشر بشه، داکر دسکتاپ یا همون بک‌اند جایگزینه
- حذف پوشه محدودیت داره (حداکثر ۵۰۰ فایل / ۵۰ مگابایت پشتیبان) و ریشهٔ فضای کاری و `.git` هیچ‌وقت حذف نمی‌شن
- بازگردانی فقط **محتوای فایل‌ها** رو برمی‌گردونه — دستورهایی که قبلاً اجرا شدن، نصب‌ها و اثرات شبکه برگشت‌پذیر نیستن (رابط کاربری هم همین رو می‌گه)
- حلقهٔ عامل هیچ‌وقت برای یه اقدام ناموفق ادعای موفقیت نمی‌کنه؛ اگه چیزی انجام نشد، می‌گه چی شد و چی نشد
(بزودی همشون درست میشن)
