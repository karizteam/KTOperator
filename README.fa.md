**این ktOperator است** یک عامل هوش مصنوعی امن و چندارائه‌دهنده‌ای که در ترمینال اجرا می‌شود. کافی است وظیفه‌ای را با زبان طبیعی توضیح دهید؛ مثلاً «معماری این پروژه را بررسی کن» یا «آزمون‌ها را اجرا کن و خطاها را برطرف کن». عامل می‌تواند برنامه‌ریزی کند، فایل‌ها را بخواند و بنویسد و دستورات را اجرا کند؛ آن هم **در محدوده فضای کاری‌ای که صریحاً مجاز کرده‌اید** و تحت نظارت یک موتور سیاست‌گذاری مستقل از مدل هوش مصنوعی.

```bash
ktoperator
```

```bash
operator run "این پروژه را تحلیل کن و معماری آن را توضیح بده"
operator plan "آزمون‌ها را اجرا کن و خطاها را خلاصه کن"
```

دستور اول کنسول تعاملی را اجرا می‌کند. دستور `run` وظیفه را اجرا می‌کند و `plan` فقط برنامه را نمایش می‌دهد و هیچ دستوری اجرا نمی‌کند.

## ✨ امکانات اصلی

- **💬 کنسول تعاملی واقعی** — راه‌اندازی اولیه فقط یک‌بار انجام می‌شود؛ سپس با یک محیط گفت‌وگوی تعاملی، پاسخ‌های قالب‌بندی‌شده و جریانی دریافت می‌کنید. پشتیبانی از عنوان‌ها، فهرست‌ها، بلوک‌های کد، نمایش صحیح فارسی و راست‌چین، بازیابی پیام‌های قبلی با کلیدهای `↑` و `↓`، ادامه نشست با `/resume` و توقف وظیفه با `Ctrl+C` بدون بستن کنسول.
- **📦 نمایش تغییرات پس از هر اجرا** — فایل‌ها، پوشه‌ها، برنامه‌ها، لینک‌ها و دستورهای مرتبط با اجرای عامل در یک کادر مشخص نمایش داده می‌شوند.
- **🧭 دسترسی پویا به مسیرها** — اگر به مسیری خارج از فضای کاری نیاز داشته باشید، مانند `C:\` یا `D:\projects\shop`، عامل می‌تواند برای دسترسی فقط‌خواندنی به آن مسیر درخواست مجوز کند. نوشتن فایل‌ها همچنان به فضای کاری محدود است.
- **🖥️ تعامل با دسکتاپ و وب** — اجرای برنامه‌هایی مانند Chrome و Edge، بازکردن لینک‌ها، جست‌وجوی وب و دریافت محتوای صفحات؛ با اعتبارسنجی URL پیش از دسترسی.
- **🧰 ۳۲ ابزار** — مدیریت فایل‌ها، جست‌وجو، تولید Diff، بررسی پروژه و وضعیت Git، اجرای آزمون‌ها و اسکریپت‌های TypeScript، Lint و Build، اجرای دستورات در محیط کنترل‌شده، مدیریت فرایندها، دریافت اطلاعات سیستم و تعامل با وب و دسکتاپ.
- **🔐 امنیت به‌صورت پیش‌فرض** — چهار سطح تأیید مجوز، اجرای ایزوله‌شده، دفاع در برابر Prompt Injection، محافظت از اطلاعات محرمانه، ثبت رویدادهای حسابرسی، تهیه نسخه پشتیبان و بازگردانی تغییرات.

## 🎯 شروع سریع

```bash
ktoperator
```

در اولین اجرا، کنسول شما را از پنج مرحله عبور می‌دهد:

| مرحله | عنوان | توضیحات |
|---|---|---|
| 1️⃣ | **ارائه‌دهنده** | انتخاب OpenRouter، OpenAI، Anthropic، Google، سرویس‌های سازگار با OpenAI یا Ollama |
| 2️⃣ | **کلید API** | ورود مخفی کلید، ذخیره‌سازی با مجوز فایل محدود و آزمایش فوری اتصال |
| 3️⃣ | **مدل** | دریافت فهرست زنده مدل‌های ارائه‌دهنده، انتخاب مدل یا واردکردن شناسه آن |
| 4️⃣ | **فضای کاری** | تعیین پوشه‌ای که عامل اجازه فعالیت در آن را دارد |
| 5️⃣ | **محیط گفت‌وگو** | تعریف وظایف و مشاهده درخواست‌های مجوز، تفاوت فایل‌ها و خروجی ابزارها |

در اجراهای بعدی، مستقیماً وارد محیط گفت‌وگو می‌شوید.

### دستورات داخل کنسول

| دستور | کاربرد |
|---|---|
| `/help` · `/status` | نمایش راهنما و وضعیت نشست |
| `/provider` · `/model` | تغییر ارائه‌دهنده و مدل |
| `/workspace` · `/workspace [path]` | مشاهده یا تعیین مجدد فضای کاری |
| `/access` · `/access list` · `/access clear` | مشاهده یا پاک‌کردن مجوزهای مسیرهای خارج از فضای کاری |
| `/sandbox` | بررسی محیط‌های ایزوله‌سازی و وضعیت آن‌ها |
| `/resume` · `/resume [id]` | ادامه یک نشست قبلی با حفظ زمینه آن |
| `/doctor` | بررسی وضعیت محیط اجرا |
| `/clear` | پاک‌کردن زمینه گفت‌وگو |
| `/exit` | خروج از کنسول |

## 🧾 دستورات خط فرمان (CLI)

| دستور | کاربرد |
|---|---|
| `ktoperator` · `operator chat` | اجرای کنسول تعاملی |
| `operator run "<task>"` | اجرای کامل عامل؛ همراه با گزینه‌های `--dry-run`، `--yes read\|write\|all`، `--json` و `--max-steps` |
| `operator plan "<task>"` | برنامه‌ریزی بدون اجرای وظیفه |
| `operator init` | ایجاد پوشه تنظیمات و مقادیر پیش‌فرض |
| `operator doctor` | بررسی و عیب‌یابی محیط اجرا |
| `operator provider list/add/test/remove` | مدیریت پروفایل ارائه‌دهندگان؛ بدون نمایش کلیدها |
| `operator model list` | نمایش مدل‌ها و قابلیت‌های هر ارائه‌دهنده |
| `operator workspace select/show` | انتخاب و بررسی فضای کاری |
| `operator session list` · `operator history [id]` | نمایش نشست‌های اخیر، تاریخچه و گزارش حسابرسی |
| `operator sandbox status` | بررسی محیط‌های ایزوله‌سازی و وضعیت فعال آن‌ها |
| `operator config show/set/path` | مشاهده، تغییر و یافتن مسیر تنظیمات با اعتبارسنجی ساختار |
| `operator backups [id]` · `operator rollback <id>` | مشاهده نسخه‌های پشتیبان و بازگردانی تغییرات |

گزینه‌های عمومی: `--json`، `--no-color`، `-v` و `--version`.

## 🔌 ارائه‌دهندگان هوش مصنوعی

| ارائه‌دهنده | توضیحات |
|---|---|
| 🟠 **OpenRouter** | پشتیبانی ویژه از دریافت فهرست مدل‌ها، تشخیص قابلیت هر مدل و محاسبه مصرف توکن و هزینه |
| 🟢 **OpenAI** | پشتیبانی از `OPENAI_API_KEY` یا ذخیره‌سازی محلی محافظت‌شده |
| 🟠 **Anthropic** | پشتیبانی از `ANTHROPIC_API_KEY` |
| 🔵 **Google Gemini** | پشتیبانی از `GOOGLE_API_KEY` |
| 🔗 **سرویس‌های سازگار با OpenAI** | اتصال به هر نقطه پایانی سازگار که مشخص کنید |
| 🐳 **Ollama** | اجرای مدل‌های محلی، بدون نیاز به اتصال اینترنت یا کلید API |

خطاهای احراز هویت، اعتبار حساب، محدودیت نرخ درخواست و در دسترس نبودن مدل‌ها به‌شکل یکپارچه مدیریت می‌شوند؛ از جمله پشتیبانی از `Retry-After`.

نقطه‌های پایانی سفارشی نیز مطابق [قوانین امنیتی SSRF](docs/security.md) بررسی می‌شوند: استفاده از HTTPS، ممنوعیت قراردادن اطلاعات احراز هویت در URL و جلوگیری از تغییر مسیرهای ناامن. دسترسی به آدرس‌های خصوصی فقط در شرایط مورد اعتماد و با تنظیم `trustedLocal` مجاز است.

## 🛡️ مدل امنیتی

> مدل پیشنهاد می‌دهد؛ موتور سیاست‌گذاری تصمیم نهایی را می‌گیرد.

- **🧱 مرز فضای کاری:** بررسی مسیر canonical با `realpath`، جلوگیری از خروج از محدوده مجاز از طریق Symlink و Junction، رد فایل‌های دستگاهی و اعمال محدودیت اندازه فایل.
- **📦 اجرای ایزوله یا عدم اجرا:** دستورات در Docker با محدودیت شبکه، حذف قابلیت‌های اضافی و فایل‌سیستم ریشه فقط‌خواندنی اجرا می‌شوند. اگر محیط ایزوله‌سازی در دسترس نباشد، اجرای دستور بدون آن به‌صورت خودکار مجاز نمی‌شود و رد خواهد شد.
- **⚖️ چهار سطح تأیید مجوز:** خواندن، نوشتن قابل‌بازگشت، عملیات مخرب و عملیات دارای دسترسی ویژه. عامل نمی‌تواند اقدامات خودش را تأیید کند و پیش از اقدامات مخرب، از وضعیت فایل‌ها نسخه پشتیبان تهیه می‌شود.
- **🧼 مقابله با تزریق دستور و افشای اطلاعات:** خروجی ابزارها به‌عنوان داده غیرقابل‌اعتماد بررسی می‌شود؛ کلیدها و اطلاعات محرمانه نباید در گزارش‌ها، خروجی یا فضای کاری افشا شوند.
- **📜 قابلیت حسابرسی و بازگشت:** ثبت رویدادها در قالب JSONL، ذخیره متن نشست‌ها و امکان بازگردانی فایل‌ها با `operator rollback`.

## ⚙️ پیکربندی

فایل تنظیمات در یکی از مسیرهای زیر قرار می‌گیرد:

| سیستم‌عامل | مسیر |
|---|---|
| Linux | `~/.config/operator/config.json` |
| Windows | `%APPDATA%\KarizTeam\Operator\config.json` |
| macOS | `~/Library/Application Support/KarizTeam/Operator/config.json` |

با متغیر محیطی `OPERATOR_HOME` می‌توانید مسیر پوشه تنظیمات را تغییر دهید.

کلیدهای API ابتدا از متغیرهای محیطی خوانده می‌شوند و در صورت نبودن، از محل ذخیره‌سازی محلی محافظت‌شده دریافت می‌شوند:

- `OPENROUTER_API_KEY`
- `OPENAI_API_KEY`
- `ANTHROPIC_API_KEY`
- `GOOGLE_API_KEY`

## 🧪 توسعه و آزمون

برای اجرای بررسی‌های پروژه:

```bash
npm run typecheck   # بررسی دقیق انواع در TypeScript
npm run lint        # بررسی کیفیت کد با ESLint
npm test            # اجرای ۲۶۳ آزمون واحد، امنیتی و یکپارچه
npm run build       # ساخت خروجی در dist/
npm run audit       # بررسی وابستگی‌ها
```

آزمون‌ها برای اجرا به شبکه یا کلیدهای API نیاز ندارند.

## ⚠️ محدودیت‌های شناخته‌شده

- روش جایگزین اجرای فرایندهای محدودشده، **معادل یک کانتینر ایزوله نیست** و محدودیت کامل فایل‌سیستم و شبکه یا سقف منابع حافظه و تعداد فرایندها را فراهم نمی‌کند؛ استفاده از آن باید صریحاً فعال شود.
- در ویندوز، تا زمان ارائه یک محیط مبتنی بر کانتینر ویندوزی، ایزوله‌سازی به همین روش جایگزین محدود است.
- حذف بازگشتی پوشه‌ها عمداً به‌عنوان ابزار قابل‌استفاده توسط عامل ارائه نشده است.
